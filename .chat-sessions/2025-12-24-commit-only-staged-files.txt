  ATRS Login Mechanism (Spring Security)

  POST /auth/dologin
  ├── membershipNumber: "0000000001"
  ├── password: "aaaaa11111"
  └── Returns: JSESSIONID cookie (session-based auth)

  Problem

  The MCP server's AtrsApiClient uses stateless fetch - no cookie storage between requests. Even if you add a login tool, the session cookie won't persist.

  Solution Options

  | Option        | Effort | Description                                      |

⏺ Basic Auth in Spring Security

  From SpringSecurityConfig.java:79-89:

  @Bean
  @Order(1)  // Higher priority than form login
  public SecurityFilterChain restFilterChain(HttpSecurity http) throws Exception {
      http.securityMatcher(antMatcher("/api/v1/**"));  // Only /api/v1/* endpoints
      http.sessionManagement(session ->
          session.sessionCreationPolicy(SessionCreationPolicy.STATELESS));  // No sessions
      http.httpBasic(Customizer.withDefaults());  // Enable Basic Auth
      http.csrf(csrf -> csrf.disable());  // No CSRF for API
      http.authorizeHttpRequests(authz ->
          authz.requestMatchers(antMatcher("/**")).permitAll());  // All permitted
      return http.build();
  }

  │  HTTP Request                                               │

> what will make the MCP interaction friction less. if say we add login 
methods to our MCP server. will it start sending the auth header in each

⏺ Yes, once you call login, the auth header persists in memory for all subsequent requests during that MCP session.

  Flow Comparison

  ┌─────────────────────────────────────────────────────────────┐
  │  WITHOUT login in memory                                    │
  ├─────────────────────────────────────────────────────────────┤
  │  User: "Search flights from Tokyo to Osaka"                 │
  │  MCP:  ❌ 401 Unauthorized (if endpoint needs auth)         │
  │  User: "Login with 0000000001 and aaaaa11111"               │
  │  MCP:  ✅ Logged in                                         │
  │  User: "Search flights from Tokyo to Osaka"                 │
  │  MCP:  ✅ Works (auth header sent automatically)            │
  │  User: "Book a ticket"                                      │
  │  MCP:  ✅ Works (same session, auth header still there)     │
  │                                                             │
  │  [MCP server restarts]                                      │
  │                                                             │
  │  User: "Search flights"                                     │
  │  MCP:  ❌ 401 again (credentials lost)                      │
  └─────────────────────────────────────────────────────────────┘

  Making It Frictionless

  | Approach                         | Friction | How                                          |
  |----------------------------------|----------|----------------------------------------------|
  | Manual login                     | High     | User calls login tool each session           |
  | Env credentials                  | Low      | Read from ATRS_USER / ATRS_PASSWORD env vars |
  | Config file                      | Low      | Store in ~/.atrs/credentials                 |
  | Auto-login on first auth failure | Medium   | Retry with stored creds on 401               |

  Recommended: Env-based Auto-login

  ┌─────────────────────────────────────────────────────────────┐
  │  MCP Server Startup                                         │
  ├─────────────────────────────────────────────────────────────┤
  │  1. Read ATRS_USER and ATRS_PASSWORD from env               │
  │  2. If present → auto-set credentials                       │
  │  3. All requests include auth header automatically          │
  │                                                             │
  │  User: "Search flights from Tokyo to Osaka"                 │
  │  MCP:  ✅ Works immediately (no login needed)               │
  └─────────────────────────────────────────────────────────────┘

  logout             - Clear credentials

  Usage

  Option 1: Auto-login via env vars (frictionless)

  {
    "mcpServers": {
      "atrs": {
        "command": "node",
        "args": ["dist/index.js"],
        "env": {
          "ATRS_API_BASE_URL": "http://localhost:8080/atrs",
          "ATRS_USER": "0000000001",
          "ATRS_PASSWORD": "aaaaa11111"
        }
      }
    }
  }

  Option 2: Manual login

  User: "Login with membership 0000000001"
  MCP:  [calls login tool] → "Logged in as 0000000001"
  User: "Search flights from Tokyo to Osaka"
  MCP:  [auth header automatically included] → results
