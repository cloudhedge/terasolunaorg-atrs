# AI-Assisted Migration Guide

## Capability Assessment

| Task | AI Can Do | Human Needed | Notes |
|------|-----------|--------------|-------|
| JSP → React | 70-80% | 20-30% | UI logic needs review |
| Java → Python | 60-70% | 30-40% | Business logic critical |
| Java Upgrades | 85-90% | 10-15% | Mostly mechanical |
| Reverse Engineering | 90-95% | 5-10% | AI excels here |

## Phased Migration Workflow

```
PHASE 1: Analysis (AI: 95%)
├── Generate architecture docs from code
├── Map dependencies & data flows
├── Identify migration risks
└── Create ER diagrams, API specs

PHASE 2: Scaffolding (AI: 85%)
├── Generate React project structure
├── Create REST API endpoints from Controllers
├── Generate DTOs from existing Form beans
└── Setup routing, state management boilerplate

PHASE 3: Code Conversion (AI: 70%) ← HUMAN REVIEW CRITICAL
├── Convert JSP views → React components
├── Transform business logic
├── Migrate security config
└── Convert MyBatis mappers → target ORM

PHASE 4: Testing & Validation (AI: 50%) ← HUMAN HEAVY
├── Generate test scaffolding
├── Validate business rules match original
├── Edge case testing
└── Performance validation
```

## Human Intervention Required

| Area | Why |
|------|-----|
| Business Logic Validation | AI doesn't know if `calculateFare()` is correct |
| Edge Cases | Domain knowledge (fare rules, booking constraints) |
| Security Review | Auth flows, session handling need expert review |
| UX Decisions | JSP → React isn't 1:1, needs design choices |
| Integration Testing | Real database, external services |
| Performance Tuning | Requires runtime profiling |

## Claude Code Workflow

### Step 1: Analyze (1-2 days)
```bash
claude "Analyze atrs-domain/, generate class diagram and API spec"
```

### Step 2: Generate REST APIs (2-3 days)
```bash
claude "Convert TicketReserveController to REST API with DTOs"
# Review & test each endpoint
```

### Step 3: Convert JSP to React (5-7 days)
```bash
claude "Convert flight-search.jsp to React component"
# Human: Test, fix edge cases, improve UX
```

### Step 4: Validate Business Logic (3-5 days)
```bash
claude "Explain what FareCalculationSharedService does"
# Human: Validate calculations, test edge cases
```

## Recommended Migration Order

1. **Auth (a0/a1/a2)** - Smallest, tests security patterns
2. **Tickets (b0/b1/b2)** - Core business logic
3. **Members (c0/c1/c2)** - CRUD operations
4. **History (d1)** - Read-only, simplest

## Key Takeaway

```
AI accelerates migration by 3-5x
BUT human oversight is NON-NEGOTIABLE for:
  ✗ Business rule correctness
  ✗ Security validation
  ✗ Edge case handling
  ✗ Final QA & sign-off

Think of AI as: SKILLED JUNIOR DEV that needs code review
```
