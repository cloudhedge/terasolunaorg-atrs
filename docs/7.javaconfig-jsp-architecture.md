# JavaConfig-JSP Project Structure

## Overview

```
JavaConfig-JSP/atrs/
├── atrs-domain/      # Business logic & services
├── atrs-env/         # Environment configuration
├── atrs-initdb/      # Database initialization scripts
├── atrs-web/         # Web layer (controllers, API, config)
└── pom.xml           # Parent Maven POM
```

## Module Breakdown

### 1. `atrs-domain/` - Business Logic Layer

Contains all business services organized by feature code:

| Package | Feature | Contents |
|---------|---------|----------|
| `a0/` | Membership Shared | Shared membership utilities |
| `a1/` | Auth Login | User authentication, login service, error codes |
| `a2/` | Auth Logout | Logout service |
| `b0/` | Ticket Shared | Shared ticket utilities, `InvalidFlightException` |
| `b1/` | Ticket Search | Flight search, vacancy info, search criteria DTOs |
| `b2/` | Ticket Reserve | Reservation logic, error codes |
| `c0/` | Member Shared | Member error codes |
| `c1/` | Member Register | New member registration |
| `c2/` | Member Update | Member profile updates |
| `d1/` | History Report | Reservation history reporting |

**Pattern**: Each feature has `*Service.java` (interface) + `*ServiceImpl.java` (implementation)

---

### 2. `atrs-env/` - Environment Configuration

```
atrs-env/
├── configs/tomcat10-postgresql/   # Tomcat + PostgreSQL datasource config
└── src/main/
    ├── java/.../config/app/       # AtrsEnvConfig.java (infra beans)
    └── resources/
        ├── META-INF/spring/       # atrs-infra.properties (DB settings)
        └── logback.xml            # Logging config
```

---

### 3. `atrs-initdb/` - Database Scripts

SQL execution order for PostgreSQL:
```
00000_drop_all_tables.sql      # Clean slate
00100_create_all_tables.sql    # Schema creation
00200_insert_fixed_value.sql   # Reference data
00210_insert_route.sql         # Flight routes
00220_insert_flight_master.sql # Flight master data
00230_insert_member.sql        # Test members
00240_insert_peak_time.sql     # Peak pricing periods
00250_insert_flight.sql        # Flight instances
```

---

### 4. `atrs-web/` - Web Layer

```
atrs-web/src/main/java/.../
├── api/                    # REST API
│   ├── common/error/       # Global exception handling
│   ├── common/util/        # Utilities
│   ├── flight/             # Flight search REST endpoints
│   └── ticket/             # Ticket reservation REST endpoints
├── app/                    # MVC Controllers
│   ├── a1/                 # Login controller
│   ├── b0/                 # (ticket shared - empty)
│   └── c2/                 # Member update controller + form
└── config/                 # Spring Configuration
    ├── app/                # ApplicationContextConfig
    └── web/                # SpringMvcConfig, SecurityConfig
```

## Key Observations

1. **Feature-based packaging**: Uses codes (a0-a2, b0-b2, c0-c2, d1) to organize features
2. **Separation of concerns**: Domain logic isolated from web layer
3. **Dual API style**: Both traditional MVC (`app/`) and REST API (`api/`)
4. **JavaConfig**: No XML Spring config - uses `@Configuration` classes in `config/` packages
